# 刻度（Praxis Path）

一个以项目为锚点、以验证为驱动的本地优先个人任务管理系统。它围绕“现实触发 → 问题 → 方案 → 结果 → 验证 → 修正”组织实践，而不是围绕日期堆积待办事项。

## 功能

- 项目创建、编辑、筛选、搜索、状态流转与删除
- 问题、方案、结果节点的管理、排序和双轨日志
- 里程碑验证方式、通过标准、结果和感受
- 里程碑或项目结束后的结构化审视
- IndexedDB 本地实时持久化
- 本机核心任务 HTTP GET 接口（开发模式自动同步、持久化最后快照）
- Chrome / Edge 桌面版自动文件快照、历史恢复与平衡保留策略
- JSON 备份导出、合并导入和覆盖恢复
- 只读分享：把单个项目导出为自包含 HTML 快照，上传静态托管后供他人查看
- 响应式桌面优先界面

## 本地运行

需要 Node.js 20 或更高版本。

```bash
npm install
npm run dev
```

浏览器访问终端输出的本地地址。工作数据实时保存在该地址对应的 IndexedDB 中；桌面版 Chrome / Edge 可以在“数据设置”中授权一个电脑文件夹，建立浏览器之外的自动快照。

## 核心任务 HTTP 接口（本机）

`npm run dev` 会同时启动只监听 `127.0.0.1` 的只读接口，默认地址：

```bash
curl http://127.0.0.1:5174/api/core-tasks
```

先用同一浏览器、同一地址打开存有任务的管理系统（例如 `http://localhost:5173`），无需停留在“核心聚焦”页面。页面初次加载及数据变化后会自动同步；同步失败每 5 秒重试，页面可见时还会每 30 秒刷新快照。**IndexedDB 仍是权威数据源**，这个接口不是数据库，也不能修改节点或取消核心。

响应为 UTF-8 JSON，按节点更新时间倒序排列。每个任务严格包含六个字段：

```json
{
  "syncedAt": "2026-01-02T03:04:06.000Z",
  "tasks": [
    {
      "projectName": "示例项目",
      "nodeType": "question",
      "content": "需要验证的 **核心问题**",
      "status": "advancing",
      "updatedAt": "2026-01-02T03:04:05.000Z",
      "url": "http://localhost:5173/projects/project-id?node=node-id"
    }
  ]
}
```

- `projectName`：项目名称。
- `nodeType`：`question`（问题）、`solution`（方案）、`result`（结果）、`assumption`（假设）、`vulnerability`（缺陷）。
- `content`：完整节点内容，保留 Markdown 原文，不截断，不含附加日志。
- `status`：普通节点为 `exploring`、`advancing`、`paused`、`completed`、`abandoned`；缺陷节点为 `unexplored`、`patched`、`open`、`conquered`；无状态节点（如假设）为 `null`。
- `updatedAt`：节点自身的 ISO 8601 更新时间，不是项目更新时间。
- `url`：打开所属项目并定位节点的绝对链接，使用同步页面的来源地址。应在存有该 IndexedDB 数据的浏览器中打开；`localhost` 和 `127.0.0.1` 属于不同来源，请勿随意切换。

项目状态为 `completed` 或 `abandoned` 时，其全部核心节点都会排除；仍进行中的项目，即使核心节点本身已完成也保留。无核心任务时返回 HTTP 200 和 `tasks: []`。从未同步或快照损坏且尚未重新同步时返回 HTTP 503（`error: "not_synced"`），避免把“数据不可用”误认为“没有任务”。调用者应检查 HTTP 状态码。

### 生命周期与数据时效

- 网页关闭后，只要 `npm run dev` 仍运行，接口继续返回最后一次成功同步的数据。`syncedAt` 是服务接收并保存快照的时间，不保证网页当前在线；请根据调用场景判断是否过旧。
- 停止开发服务后接口不可用；重启后从项目根目录的 `.core-tasks/snapshot.json` 恢复最后快照。该目录已加入 gitignore，可在停服后删除以清除导出缓存；它不是完整备份。
- 端口冲突会明确导致启动失败，不自动换端口。可在启动前设置环境变量 `CORE_TASKS_PORT`（例如 PowerShell：`$env:CORE_TASKS_PORT=5274; npm run dev`）。此变量从启动进程读取，不从 `.env` 文件读取。
- 当前同步请求上限为 2 MiB；超限会保留上一份快照，浏览器控制台提示同步失败。`syncedAt` 不再更新，可用于发现这种情况。
- 当前仅支持 `npm run dev`，不在 `npm run preview` 或静态部署中启用，不影响现有静态分享页。
- 仅允许本机页面同步；通过局域网或 Tailscale 地址打开页面不会同步。若多个浏览器或不同来源各存了一份独立数据，以最后成功同步者为准；建议只用一个固定来源作为日常工作区。

### 安全边界

接口仅绑定回环地址，不提供 CORS 授权、不接受带 Origin 的浏览器读取请求，并校验本机 Host；内部快照同步仅接受本机同源 JSON 请求。对外 GET 接口不提供写操作。**没有 API token：本机其他程序也能读取任务内容**；快照以明文保存在本机。不要将该接口反向代理或转发到局域网、公网。

## 只读分享（静态快照）

把指定项目导出成一个自包含的只读 HTML 文件：项目数据内嵌在文件里，查看者用浏览器打开即可看到路线图、节点内容（含 Markdown/公式/代码高亮）、可选的里程碑与复盘，但不存在任何修改入口——只读是结构性的，查看页中没有写入代码路径。

### 使用步骤

1. 一次性准备（或 viewer 代码更新后重跑）：`npm run build:share-template`，生成 `public/share/viewer-template.html`（产物已 gitignore，只存在于本机）
2. 打开项目 → 点“分享”→ 勾选内容范围（里程碑默认包含，复盘默认不包含）、选择主题、可选设置口令 → 生成文件
3. 把文件上传到任意静态托管即获得只读链接，例如：
   - Netlify Drop：浏览器拖拽即用
   - Cloudflare Pages / GitHub Pages：放入仓库或直接上传
4. 更新内容：重新生成并**同名上传**，链接保持不变；撤销分享：删除线上文件

### 数据安全边界

- 静态应用无账号体系，分享只上传这一份快照文件；开发模式额外提供仅本机可读的核心任务接口和明文缓存（见上文），不会自动上传到外部服务
- 口令模式：整个数据（含项目名）以 AES-GCM-256 加密嵌入，密钥由口令经 PBKDF2-SHA256（31 万次迭代、随机盐）派生；口令不保存在任何地方，忘记即无法恢复
- 诚实说明：口令加密防的是链接泄露与托管平台翻看文件；若托管方恶意篡改页面代码，仍可能窃取口令——对高敏感内容请选择可信托管或不要分享
- 无口令模式下，任何获得链接的人都能查看内容，请只用于不敏感的项目

## 数据安全

建议在“数据设置”中连接一个普通文件夹或 OneDrive 同步文件夹。数据修改静默 10 秒后会自动创建不可变快照，并按“24 小时内最多 10 份、30 天内每天一份、更早每月一份”自动保留。清理站点数据不会删除这些文件，但之后需要重新选择该目录。手动 JSON 导出仍作为额外的可携带备份方式。
