# 提问

我为自己准备了如何读文献的科研流程。

首先，自己要有一个战略上的大问题，例如“怎么把密码学、分布式与联邦学习结合”。根据这个战略问题，设计关键词去检索文献。

看到列出的文献列表，根据标题和摘要做初筛。要是标题明确是与原创技术论文无关的，例如是 survey, book 之类，那就直接略过；要是标题看上去比较相关，那就点进去看看摘要。要是摘要看起来也无关，引用量也不高，那就忽略；要是摘要看起来有点关联，那就下载到 zotero 里。

接下来把论文原文发给 LLM 看，大概总结一下内容。根据摘要和 LLM 总结的大概内容，自己想一想攻击战术上的小问题：我怎么攻破它？这里就对应三类小问题：攻击边界问题、权衡取舍问题和现实落地问题。

要是看了摘要和 LLM 的总结，我也没什么想法的话，大概有几种可能：第一，我刚开始看类似领域的论文，暂时没什么想法；第二，这个论文的框架有点完美了，一时间看不出问题来；第三，没看懂摘要和总结。

第一个问题好解决，让 LLM 给我点启发，或者我去看看作者自己说有什么缺陷，然后我自己纸面推演或者代码复现一下。第二个有点麻烦，如果一个框架完美到连作者自己都没什么缺陷需要承认，那就学它完美在何处吧。第三个也好解决，结合论文原文多问问你关于我不懂的地方就好。

那如果有新问题了，不仅可以与 LLM 继续进行纸面推演，更重要的是自己也去用代码复现一下，看看我提出的这个问题是否的确存在。要是连复现都的确存在这种问题，而且确定是方案固有而不是我运行环境的特有，那我之前那个战略上的大问题就可以更细化了，例如“怎么把密码学、分布式与联邦学习结合”就可以变为“怎么把密码学、分布式与联邦学习结合，特别是避免……的问题”，接下来的关键词检索也可以更细化。

除了问问题以外，也要学习每个原创技术的哲思：为什么这样设计？这个好说，因为我在读教材和综述的时候就已经习惯这种思想模式了。思考哲思，主要是为了自己设计方案的时候能够做到同结构迁移。

那么，何时结束一篇文献的阅读？一般地只要能够找到一个确凿的缺陷，基本上就能够暂时结束这篇论文的阅读了。然后我们可以找其他相关论文，看看是否有人填上了这个缺陷，以及他们又暴露了哪些新缺陷。如果没人填这个缺陷，那好说，我来填；要是有人填上了，那还可以回看这篇论文，看看是否其他缺陷也被人填上了。这样就进一步扩充了我们之前的科研工作流。

但我在想，怎么可视化一下这个流程？我之前给自己写了一个可视化任务系统，就像游戏任务一样管理我的当前任务。我将任务按不同项目分类管理，例如阅读密码学教材和阅读分布式教材是两个不同项目。每个项目自己维护一个路线图，路线图是由任务节点构成的 RAG，一个任务节点可以是问题节点（我想要解决什么问题）、方案节点（打算怎么做）和结果节点（获得了什么结果）。我已经用这个系统很好地维护了我的密码学入门，你认为这个系统能直接用来维护上面说到的科研工作流吗？还是有必要增加一些功能呢？

# 回答

现有的系统（问题-方案-结果节点构成的 RAG）已经非常先进，但直接用来维护科研工作流，还差最后一块拼图。

因为**教科书的知识是树状的（继承关系），而科研论文的演进是网状的（攻防关系）**。你现有的“问题→方案→结果”是**线性流水线**，而科研的本质是**对抗性博弈**。

为了让你的路线图完美适配科研，我建议在现有节点类型和关系上，增加下方功能。

### 1. 新增必须的节点类型

除了你现有的问题（Q）、方案（S）、结果（R）外，需要增加：

- **假设/约束节点（A - Assumption）**：这个方案在什么前提下才成立？（例如：对手不能是量子计算机、通信是同步的）。这是所有安全的基石。
- **缺陷/漏洞节点（V - Vulnerability）**：这是你“攻击者视角”的产物。它必须连接到特定的假设节点（即：**当假设A不成立时，缺陷V出现**）。

### 2. 新增关键的“对抗性”边关系

你原有的边可能是 `提出`、`实现`。现在必须为这些有向边加入演进逻辑：

- **`暴露` （Exposes）**：方案S ——暴露——> 缺陷V。（代表你找到了它的命门）。
- **`填补` （Patches）**：方案S2 ——填补——> 缺陷V。（代表后续工作解决了这个缺陷）。
- **`继承` （Inherits）**：方案S2 ——继承——> 方案S。（代表后续工作沿用了核心框架，只改了某个零件，比如你把D-H改成Kyber，就是继承+替换）。
- **`弱化` （Weakens）**：方案S2 ——弱化——> 假设A。（代表为了效率，新方案放松了某个安全假设）。

### 3. 针对你“没人填我就填”的战术，修改任务状态

原有问题（Q）、方案（S）、结果（R）节点的五种状态属性不变。

无需为**假设/约束节点（A）**引入状态属性，而需要为每个**缺陷节点（V）**引入状态属性为：

- **`待探索`**（你刚发现，还不知道有没有人填）。
- **`已被填`**（找到了填补论文，链接过去）。
- **`待攻克`**（搜索后发现确实没人填，这就是你的潜在创新点，系统将自动把它提升为最高优先级任务）。
- **`已攻克`** (发现没人填，而且我自己成功攻克了)。

新类型节点仍然允许附加日志。

### 4. 允许使用任意有向图

新增项目类别：“科研”。普通项目仍然沿用原有的RAG路线图，科研项目则允许用**任意有向图**。

科研项目路线图中，不再允许“设为当前目标”从而高亮RAG中的一条长链，改为允许对若干节点**设为重点关注**从而高亮部分节点以及该节点的所有入边和出边。

项目类别在项目初创时确定，后续**不允许更改**。

# 在现有系统基础上做最小改进

“科研”项目中，节点列表、里程碑、审视功能、路线图的Route Atlas，以及主题风格等直接沿用，无需另起炉灶。

采用任意有向图作为路线图的react flow界面中，取消收起支线的功能，显示所有节点；ROUTE统计只需记录节点和边的个数即可，不再统计支线数量；取消“聚焦路线”按钮，定位目标按钮改为搜索节点内容后跳转到节点；添加节点按钮默认为创建独立问题节点。

选中某节点时，该节点的“据点情报”面板中，取消“继续推进”、“取消追踪”和“创建支线“按钮，保留“设为里程碑”、“编辑”和“删除”按钮；“设为当前目标”按钮改为“设为重点关注”，单击后该节点以及该节点的所有入边和出边高亮，且“设为重点关注”变为“取消重点关注”。只能删除非重点关注的节点，且单击删除按钮后同样弹出确认窗口，节点删除后所有相关边全部级联删除。

原本连接两个节点以新增边的功能保留，且现在允许出现环，但不允许出现自环（自己连接自己）。每新增一条边都询问边的类型：暴露、填补、继承或弱化。无需为边准备附加日志。允许在路线图中选中边，然后修改边的类型。双击以删除边的功能保留。

## 修复结果

问题原因是 `TaskGraphNode.tsx` 的 `typeMeta` 仍然只包含普通项目的三种节点类型，科研项目加载 `assumption` 或 `vulnerability` 节点时无法取得 `label` 和 `icon`。

已完成以下修复：

- 为 `assumption` 添加“假设”标签和 `HelpCircle` 图标
- 为 `vulnerability` 添加“缺陷”标签和 `ShieldAlert` 图标
- 更新技术视图节点编号：`ASM`、`VUL`
- 更新游戏视图节点编号：`A`、`V`

验证结果：

- TypeScript 类型检查通过
- 相关文件无 linter 错误
- 31 个单元测试全部通过
